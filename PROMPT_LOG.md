## Задание Повышенная сложность №1: Создание полноценного веб-приложения
**Инструмент:** Deepseek и GPT-4
### Промпт 1
**Промпт:** 
Создай веб-приложение на FastAPI + SQLAlchemy + Jinja2 + SQLite, предметная область: система управления рестораном. Функционал (строго по заданию):
1) Аутентификация: регистрация, логин, JWT (httpOnly cookie). Роли user/admin.
2) Основная сущность CRUD: Заказы (поля: id, user_id, стол, статус new/cooking/ready/paid, дата, сумма).
3) Дополнительные сущности (≥3 связанных): Столы, Меню, Позиции заказа.
4) Отчёты/аналитика: страница с выручкой за сегодня, кол-вом заказов по статусам, топ блюд, загрузкой столов.
5) Админ-панель: доступ admin, управление пользователями (смена роли), столами, меню, удаление заказов. 
6) Кухня: страница для изменения статусов заказов (new→cooking→ready) — доступ всем авторизованным. Выведи все файлы проекта.   

Так же в проект задана инструкция для более точного написания кода:  
Ты — senior Python разработчик. Генерируй код строго по требованиям:  
1. Чистота кода: соблюдай SOLID, DRY, разделение ответственности (модели, схемы, роутеры, сервисы, зависимости). 
2. Тесты: напиши покрывающие все сценарии (pytest + pytest-asyncio). Протестируй: регистрацию, логин, создание заказа, изменение статуса, админ-доступ, отчёты. Фикстуры для БД (SQLite in-memory).
3. Docker: добавь Dockerfile и docker-compose.yml (один сервис — приложение с SQLite). Контейнер запускается командой docker-compose up --build.
4. Окружение: все переменные через os.getenv() и файл .env (пример .env.example). Используй python-dotenv.
5. README.md: инструкция по установке, запуску (локально и через Docker), переменные окружения, тесты.
6. Безопасность: JWT в httpOnly cookie, пароли хэшировать, CORS не открывать без необходимости.
7. Логирование: базовое (print или logger) для ошибок.
8. Структура проекта: app/ (routers/, models.py, schemas.py, dependencies.py, services/), tests/, templates/, статика.
9. Проводи рефакторинг и ревью корректно следуя правилам, старайся не выводить ложные замечания и правильно указывать на улучшения проекта.

### Промпт 5
**Промпт:** Официант (waiter) – может просматривать меню, столы, создавать заказы, видеть свои заказы (и статусы), но не управляет кухней и аналитикой.
Повар (cook) – видит только страницу кухни (активные заказы), может менять статусы new→cooking→ready.
Админ (admin) – имеет полный доступ (включая управление пользователями, меню, столами, аналитику).
**Результат:** введены роли waiter, cook, admin. Созданы зависимости waiter_required, cook_required, навигация динамически скрывает/показывает пункты меню, доступ к страницам ограничен по ролям.
Регистрация новых пользователей автоматически присваивает им роль официанта (waiter), а роль повара (cook) может назначить только администратор через админ-панель, что соответствует реальной практике ресторанного управления, где сотрудники с разными обязанностями создаются и наделяются правами исключительно руководителем.
